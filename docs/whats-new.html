What's New in Orbital X v2.4.0

Welcome to Orbital X v2.4.0. This release delivers high-speed inline code suggestions (<2s latency), screenshot-to-agent multimodal intelligence, transactional VFS in-editor diff review, dedicated structured error handling, and Apple HIG notification center design.

Download v2.4.0 View on GitHub ↗
Performance & Ergonomics
High-Speed Inline Code Suggestions (<2s Latency)
What's New: Decoupled completion inference from primary chat reasoning. Configure a dedicated lightweight model (e.g. qwen2.5-coder:1.5b) for ghost text completions that never interrupts ongoing agent conversations.
What Changed: Tight completion budgets (36 tokens) and targeted context (400 chars prefix / 120 chars suffix) backed by an in-memory LRU cache (<20ms for repeated tokens) and immediate keystroke cancellation.
How It Helps: Accept inline ghost text instantly with native Monaco Tab keybinding. Live millisecond latency telemetry streams to the status bar (#sb-complete-indicator).
Why It Matters: Eliminates 10-second completion stalls. You get fast, consistent suggestions engineered specifically for local hardware constraints.
Multimodal Visual Intelligence
Screenshot-to-Agent & Visual Debugging
What's New: Paste screenshots directly from clipboard into the prompt composer (Ctrl+V), drag and drop image files, or use the dedicated image attachment button with 1-click thumbnail previews.
What Changed: Honest model validation with OX-415 error guidance. If a text-only model is selected, the IDE guides you to a vision-capable model (Ollama llama3.2-vision, gpt-4o, claude-3-5-sonnet, gemini-2.0-flash) instead of hallucinating.
How It Helps: Debug CSS visual bugs, inspect mockups, and troubleshoot UI layout defects by showing the agent the exact screen render. Attached images render directly in chat with full-screen zoom.
Why It Matters: Full visual intelligence integrated into local and cloud workflows without clunky file dialogues or fake image understanding.
Transactional Code Integrity
In-Editor VFS Review & Diff Acceptance Bar
What's New: Docked top-mounted review bar inside Monaco displaying filename, added lines (+green), and removed lines (-red) before changes are written to disk.
What Changed: AI-proposed modifications are staged inside the Virtual File System shadow layer. Interactive inline green/red diff highlights appear directly inside the active editor view.
How It Helps: Review changes line-by-line. Click [Accept] to commit changes to disk or [Reject] to revert to original code without touching git working state.
Why It Matters: Zero unverified edits. You retain complete human-in-the-loop control over every file the agent attempts to modify.
Developer Diagnostic Suite
Structured OX Error Framework & 1-Click Fixes
What's New: Standardized error codes across the entire IDE: OX-101 (Syntax & Diagnostics), OX-403 (Sandbox Policy), OX-409 (VFS Conflicts), OX-415 (Vision Required), and OX-503 (Ollama Daemon Offline).
What Changed: Replaced raw stack traces with actionable error cards featuring plain-English explanations, 1-click remediation buttons, clipboard export, and collapsible technical logs.
How It Helps: Instantly test Ollama connectivity, switch sandbox safety modes, or auto-fix compiler errors without searching docs or opening external terminals.
Why It Matters: Turns cryptic runtime errors into guided, self-healing developer workflows directly inside the IDE timeline.
Apple HIG UI/UX Redesign
Liquid Glass Activity & Notification Center
What's New: 28px backdrop blur vibrancy, squircle category badges, Apple-style segmented filter track (All, Build, Security, Agent), and clean empty/loading states.
What Changed: Completely eliminated emoji UI in favor of crisp SVG vector icons, subtle borders, refined card typography, and reliable Clear All / dismiss interactions.
How It Helps: Track background builds, security sandbox decisions, and agent operations without visual noise or permanent unnecessary scrollbars.
Why It Matters: Developer-grade notification experience comparable to macOS native utilities, VS Code, and Cursor.
Productivity & Context Staging
File Explorer Drag-and-Drop & Rich Staging
What's New: Drag any file or folder from the Explorer tree directly into the chat prompt composer to automatically tag @path in your message.
What Changed: Extended non-file context staging: stage package dependencies (package.json, Cargo.toml), compiler diagnostics, and working memory buffers to local models with one click.
How It Helps: Target local LLM attention precisely to relevant files and dependencies, minimizing context bloat and maximizing reasoning accuracy.
Why It Matters: Provides small 7B/14B parameter local models with dense, high-signal information for superior code generation.
