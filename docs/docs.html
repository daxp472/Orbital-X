Orbital X Reference Manual

Documentation Hub

Welcome to the official technical documentation for Orbital X. Orbital X is an open-source, ultra-efficient desktop coding IDE engineered on Tauri 2 and Rust. It delivers native speed, complete data confidentiality with 100% offline local model inference, durable memory, and an idle memory footprint of just ~95 MB RAM.

🔒 Air-Gapped Privacy First
Orbital X never dials home or sends telemetry. All workspace index data, memory cards, and AI inference runs locally on your machine via direct IPC or Ollama.

⚡ Quickstart & Installation

Orbital X offers official binaries across Windows, macOS, and Linux platforms.

Windows Installation

You can install Orbital X using the official Windows NSIS setup package or directly from Windows Package Manager (winget):

PowerShell / Command Prompt
winget install daxp472.OrbitalX

Alternatively, download the standalone installer Orbital X_2.3.4_x64-setup.exe from the download section.

macOS Installation

Download Orbital.X_2.3.4_aarch64.dmg for Apple Silicon (M1/M2/M3/M4) or Intel macs. Open the disk image and drag Orbital X into your Applications directory.

Linux Installation

We provide both standalone .AppImage binaries and .deb packages for Debian and Ubuntu distributions:

Bash
chmod +x Orbital.X_2.3.4_amd64.AppImage ./Orbital.X_2.3.4_amd64.AppImage

🏛️ Architecture & Native Rust IPC

Unlike legacy Electron-based editors (which bundle Chromium and Node.js for every window and consume 1.5GB to 2.2GB RAM upon launch), Orbital X separates frontend rendering from operating system execution:

  • Rust Backend Core: Handles file I/O, OS directory watchers, PTY terminal execution, workspace boundary guards, and memory index storage.
  • OS Native Webview (WebView2 / WebKit): Provides a hardware-accelerated 120+ FPS canvas for Monaco Editor and the agent workspace.
  • Zero Cross-Thread Deadlocks: File dialogs and OS calls execute asynchronously on dedicated blocking tasks, ensuring the UI remains buttery smooth.

🎛️ Tri-Mode Safety System

Orbital X features kernel-enforced sandboxing with three operational autonomy levels. You can switch modes instantly via the top header pill or status bar:

Autonomy Policy Dev Mode (Default) Agent Pro Mode User Mode
File Inspections & Searches ⚡ Automatic ⚡ Automatic 🛡️ Requires Approval
Code Edits & File Writes 🛡️ Approval Card + Monaco Diff ⚡ Auto (with Undo Journal) 🛡️ Strict Approval
Terminal Execution 🛡️ Confirmation Required ⚡ Safe build/test auto-run 🛡️ Strict Confirmation
Recommended Use Case Balanced everyday coding Fast feature generation & refactoring High-security & sensitive codebases

🧠 Local AI with Ollama

Orbital X communicates directly with Ollama on http://127.0.0.1:11434.

Step 1: Install Ollama

Download and install Ollama from ollama.com.

Step 2: Pull Your Preferred Coding Model

Terminal
# Recommended for 16GB RAM machines: ollama pull qwen2.5-coder:7b # Recommended for lightweight 8GB machines: ollama pull llama3.2:3b # High performance for 32GB+ systems: ollama pull deepseek-coder-v2:16b

Step 3: Launch Orbital X

Open Orbital X. The AI agent will auto-detect your local Ollama models. Select your active model from the top status badge and begin coding!

🧠 Two-Tier Project Memory Architecture

To deliver deep codebase comprehension without overwhelming small-context local models (8K token context windows), Orbital X employs a specialized two-tier memory design:

Tier Scope & Budget Mechanism Primary Job
Tier 1: Core Active Memory <200 tokens (Pinned to every turn) Active prompt context digest Working directory, stack hint, active editor tab, recent 6 actions, and explicit Anti-Loop Invariant instructions.
Tier 2: Information Directory Library Queried on demand via tool call query_information_directory (Rust Librarian Indexer) Deep historical memory indexed from .orbital/memory.json and all markdown changelogs in changelogs/*.md.
⚡ Anti-Loop Guarantee
By pinning only the verified completed tasks and anti-loop invariants into Tier 1 Core Memory, local models never repeat completed refactoring steps or re-scaffold files they have already created.

🔀 Smart Semantic Model Routing Engine

Orbital X supports multi-provider model routing. When enabled in Settings, the agent core inspects the incoming prompt's semantic complexity:

  • Lightweight Queries: Queries matching status checks, file searches, or simple explanations are routed to fast, low-parameter local models (e.g. qwen2.5-coder:7b or llama3.2:3b).
  • Complex Engineering: Tasks involving multi-file refactoring, security policy updates, or architectural planning can be automatically routed to high-capacity local or cloud specialists (e.g. deepseek-coder-v2 or Claude 3.5 Sonnet).

🔧 Troubleshooting & Crash Logs

If you ever experience an issue, Orbital X automatically logs crash details directly to disk on your C: drive:

Default Crash Log Path
C:\Users\<YourUsername>\.orbital\crash.log

You can inspect this file directly in Windows File Explorer or copy diagnostic details from the Developer > Copy Diagnostic Info menu.

To report a bug or request a feature, click Help > Report Issue inside Orbital X or visit our Report Issue Page.
