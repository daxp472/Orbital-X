## 1. Executive Summary & Objective

This iteration takes full control of the codebase to diagnose, repair, and harden critical regressions and UX issues:
1. **Resolution of Fatal Startup Regression (`ReferenceError: getAllBindings is not defined`):**
   - Discovered the root cause that crippled the entire application: `getAllBindings()` and `comboFromEvent(e)` were called in `src/js/app.js:initGlobalShortcuts` without being imported from `src/js/services/keybindings.js`.
   - Because `initGlobalShortcuts()` ran during `DOMContentLoaded`, the uncaught ReferenceError halted script execution immediately. As a result, subsequent event handlers (including `#btn-open-workspace`, `#welcome-open-folder-btn`, `#sidebar-root-header`, `#btn-explorer-open-folder`, `#btn-open-folder-inline`, `#header-mode-pill`, and the Pro/Dev/User mode switcher dropdown) were never attached to the DOM.
   - Properly imported `getAllBindings` and `comboFromEvent` in `src/js/app.js`, wrapped `initGlobalShortcuts()` in defensive error boundaries, and also guarded against missing imports across `settings.js` (`showConfirmDialog`) and `monaco.js` (`lastFocusedPanel`, `isMarkdownPreviewActive`).
2. **Open Workspace & Ctrl+O Folder Selection:**
   - Unified folder picker triggers across the center titlebar badge (`#btn-open-workspace`), Explorer sidebar header (`#btn-explorer-open-folder`), empty state button (`#btn-open-folder-inline`), root header (`#sidebar-root-header`), and Welcome modal (`#welcome-open-folder-btn`).
   - Implemented a direct, bulletproof global shortcut for <kbd>Ctrl+O</kbd> in both the window event listener and Monaco Editor actions (`orbital.openFolder`), ensuring folder selection opens reliably regardless of current focus.
   - Automatically unhides the sidebar and switches the active rail view to Explorer (`#rail-explorer` / `#view-explorer`) whenever a workspace is opened.
3. **Crash Log Disk Persistence on C: Drive:**
   - Eliminated the in-memory crash log bottleneck and the annoying *"Open a workspace to persist crash.log — details kept in memory"* notification.
   - Implemented `save_crash_report` in Rust (`src-tauri/src/lib.rs`), which directly appends crash and error details to disk on the C: drive (`~/.orbital/crash.log` / `C:\Users\<user>\.orbital\crash.log`), or to a user-configured directory (`localStorage['orbital_crash_log_dir']`).
   - Added an interactive *"Show in Explorer"* action to the toast notification so users can inspect the physical log file with one click.
4. **Open in Windows File Explorer:**
   - Implemented `open_in_explorer` native Rust command to open any workspace directory or select files in Windows Explorer (`explorer.exe /select,"path"`).
   - Added an *"Open Workspace in Windows File Explorer"* button (`#btn-open-in-explorer`) to the Explorer sidebar header, updated file tree context menus, and added command palette integration.
5. **Welcome Screen & Chat Continuity Restoration:**
   - Transformed the entry Welcome Screen (`#modal-welcome`) into a two-column hub:
     - **Left Column:** Prominent **📂 Open Folder / Workspace** button, New File, Clone Repository, and interactive list of Recent Workspaces with instant loading.
     - **Right Column:** Prominent **💬 Continue Yesterday's Chat / Latest Session** highlighted card, interactive list of Previous Chat Sessions with relative timestamps (e.g. *"Yesterday at 5:30 PM"*, *"Today at 10:15 AM"*, message count badges), "➕ New Chat", "📥 Import Markdown", and "📤 Export Chat".
6. **"Workspace Load Fail" Startup Error Elimination:**
   - Resolved the root cause where starting Orbital X with a missing or stale workspace path in `localStorage` caused a disruptive error toast on launch. Stale directories are now gracefully pruned and the user is greeted by the Welcome Screen.
7. **F12 & Developer Menu System Overhaul:**
   - Enabled `"devtools"` feature in `src-tauri/Cargo.toml` so WebView2 Developer Tools work in both development and production/release builds.
   - Restored global <kbd>F12</kbd> shortcut to directly toggle DevTools across the entire application without requiring users to navigate into Settings or toggle artificial mode gates.
   - Wired up the menubar "Developer" button (`#menu-developer`) to open a native-grade dropdown containing DevTools, in-app Debug Console overlay, Reload Window, Agent Debug Output toggle, and System Diagnostic info copy.
8. **Production Release Build v2.2.8:**
   - Compiled full release build and placed the Windows NSIS installer inside the root `release/` directory.

## 2. Root Cause Analysis (RCA)

### Issue A: Fatal DOM Listener Abort (`ReferenceError: getAllBindings is not defined`)
- **Root Cause:** In `src/js/app.js`, `initGlobalShortcuts` referenced `getAllBindings()` and `comboFromEvent(e)` without importing them. During app initialization in `DOMContentLoaded`, invoking `initGlobalShortcuts()` threw a fatal unhandled `ReferenceError`. Because this was uncaught, all subsequent initialization steps were aborted:
  - Open workspace click listeners (`#btn-open-workspace`, `#btn-explorer-open-folder`, `#welcome-open-folder-btn`, `#sidebar-root-header`, `#btn-open-folder-inline`) were never attached.
  - Operating mode dropdown click listeners (`#header-mode-pill`, `#mode-switcher-dropdown`, `#status-mode`) were never attached, making mode switching unresponsive.
  - Window control listeners and developer menu dropdowns were never initialized.
- **Resolution:**
  - Added explicit named imports for `getAllBindings` and `comboFromEvent` from `./services/keybindings.js` in `src/js/app.js`.
  - Wrapped `initGlobalShortcuts()` inside a `try / catch` block in `DOMContentLoaded` and added defensive null/type checks around `getAllBindings()`.
  - Added missing `showConfirmDialog` import in `src/js/components/settings.js`.
  - Corrected lexical scoping of `lastFocusedPanel` and `isMarkdownPreviewActive` in `src/js/editor/monaco.js`.

### Issue B: Crash Log Stored in Memory
- **Root Cause:** In `src/js/app.js`, `reportError()` relied on `state.workspace.rootPath` to write logs via `save_file`. When no workspace was active, it fell back to `localStorage` and toasted *"Open a workspace to persist crash.log — details kept in memory"*.
- **Resolution:** Added `save_crash_report` IPC in `src-tauri/src/lib.rs` using `dirs::home_dir().join(".orbital")`. Errors are now automatically recorded to `C:\Users\<user>\.orbital\crash.log` without requiring an open workspace.

### Issue C: Open Workspace & Ctrl+O Not Triggering Directory Load
- **Root Cause:** 
  1. Window `keydown` listener routed `Ctrl+O` through an indirection lookup which was suppressed when Monaco Editor held focus.
  2. Spawning dialog threads without proper apartment handling caused Win32 COM cross-thread deadlocks.
  3. When a folder was successfully opened, the sidebar did not switch to the Explorer view or unhide if previously collapsed.
- **Resolution:**
  1. Added top-level capture in `window.addEventListener('keydown')` and registered `orbital.openFolder` action directly on Monaco Editor instances.
  2. Refactored `open_folder_dialog` to use `tokio::task::spawn_blocking` with multi-tier fallback (WebviewWindow parented dialog, app dialog, and native `rfd`).
  3. Added explicit sidebar activation and view switching to `#view-explorer` on successful `enterWorkspace()`.

### Issue D: Open in Explorer Not Functional
- **Root Cause:** Frontend called `TerminalService::run_command` with `explorer /select,"path"`, which ran inside a spawned shell terminal session with stdout/stderr capture, causing command stalling and process detachment issues.
- **Resolution:** Implemented `open_in_explorer` in Rust using direct OS process spawning (`std::process::Command::new("explorer").arg(...)`).
