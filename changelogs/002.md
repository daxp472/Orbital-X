1. **Welcome Screen & Chat Continuity Restoration:** Transformed the entry Welcome Screen (`#modal-welcome`) into a two-column hub featuring:
   - **Left Column:** Prominent **📂 Open Folder / Workspace** button, New File, Clone Repository, and interactive list of Recent Workspaces with instant loading.
   - **Right Column:** Prominent **💬 Continue Yesterday's Chat / Latest Session** highlighted card, interactive list of Previous Chat Sessions with relative timestamps (e.g. "Yesterday at 5:30 PM", "Today at 10:15 AM", message count pill), "➕ New Chat", "📥 Import Markdown", and "📤 Export Chat".

3. **Open Workspace / Native Folder Dialog Fix:** Eliminated cross-thread COM affinity lockups in `rfd::FileDialog` on Windows by spawning the native picker on a dedicated OS thread without cross-thread parent window HWND attachment, and hardened the multi-layer fallback pipeline in `tauri.js`.
4. **F12 & Developer Menu System Overhaul:**
   - Enabled `"devtools"` feature in `src-tauri/Cargo.toml` so WebView2 Developer Tools work in both development and production/release builds.
   - Restored global <kbd>F12</kbd> shortcut to directly toggle DevTools across the entire application without requiring users to navigate into Settings or toggle artificial mode gates.
   - Wired up the menubar "Developer" button (`#menu-developer`) to open a native-grade dropdown containing DevTools, in-app Debug Console overlay, Reload Window, Agent Debug Output toggle, and System Diagnostic info copy.
5. **Quality Verification:** Verified Rust backend compilation (`cargo check`), frontend syntax (`node --check`), unit tests (`npm test`), and workspace security isolation tests.

## 2. Root Cause Analysis (RCA)

### Issue A: "Workspace Load Fail" on Startup
- **Root Cause:** In `src/js/app.js`, `tryRestoreLastWorkspace()` unconditionally invoked `enterWorkspace(last.path)` for whatever path was stored in `localStorage`. If the folder had been moved, deleted, or was inaccessible, `ws.set_root()` in Rust returned `Err("Invalid path ...: folder does not exist or is inaccessible")`. This was caught as a fatal error, firing an intrusive error toast on launch and leaving the IDE in an ambiguous half-restored state.
- **Resolution:** In `tryRestoreLastWorkspace()`, if `enterWorkspace()` fails, the stale path is silently pruned from `localStorage['orbital_recent_workspaces']`, no error toast is shown, and `openWelcomeScreen()` is smoothly displayed.

### Issue B: Welcome Screen Lacking Chat Continuity & Yesterday's Chats
- **Root Cause:** The Welcome Screen previously showed static marketing text ("What's New in v2.2.8") on the right-hand side, with no connection to previous chats, making it impossible to continue conversations from yesterday or previous sessions from the entry page.
- **Resolution:** Redesigned `#modal-welcome` in `index.html` to display a dedicated "Continue Chat" hub. Exported `getSessions()` in `chat-sessions.js` and wired up `openWelcomeScreen()` in `app.js` to dynamically render:
  - An interactive card displaying the latest conversation title, relative timestamp ("Yesterday at HH:MM", "Today", etc.), message count, and last message preview.
  - An interactive list of previous chat sessions that resumes the chosen chat, dismisses the modal, opens the Agent panel, and focuses the composer.

### Issue C: Open Folder Picker Bouncing or Failing to Appear
- **Root Cause:** In `src-tauri/src/lib.rs`, the folder picker thread called `dialog = dialog.set_parent(&win);`. On Windows, attaching the GUI thread's `HWND` as owner to an `IFileDialog` invoked on a background thread causes Win32 COM cross-thread owner window affinity lockups or immediate `RPC_E_WRONG_THREAD` failures. Furthermore, `tauri.js` contained an early `if (res === null) return null;` that prevented fallback to `@tauri-apps/plugin-dialog`.
- **Resolution:** Removed `dialog.set_parent(&win)` on the picker thread, allowing Windows Explorer to create a top-level unparented modal dialog cleanly without COM synchronization hangs, and ensured `tauri.js` attempts the secondary plugin dialog fallback if the primary IPC returns `null`.

### Issue D: F12 Menu Redirecting to Settings
- **Root Cause:** Claude Code placed developer options inside a settings tab (`spane-developer`) and blocked F12 behind an artificial `isDeveloperMode` toggle, alerting the user to go to Settings instead of opening DevTools. Additionally, Tauri's `w.open_devtools()` was not compiled into release builds because `"devtools"` was omitted from `Cargo.toml`.
- **Resolution:**
  - Added `tauri = { version = "2.12.4", features = ["devtools"] }` in `src-tauri/Cargo.toml`.
  - Updated `open_dev_tools` command in `src-tauri/src/lib.rs` to open DevTools directly.
  - Rewrote `src/js/components/developer-menu.js` so pressing <kbd>F12</kbd> anywhere directly opens DevTools (with fallback to in-app debug console).
  - Positioned the Developer menubar dropdown directly underneath the `#menu-developer` button.
